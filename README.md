# FreePushNote

一个 Windows 桌面 txt 编辑器：**写完笔记，一键推到 GitHub，自动变成在线文档站。**

用记事本的手感写东西，用 GitHub 保存和发布；不需要懂 git，也不需要为「我只想改一个错别字」走完一整套 `add / commit / push`。

> 项目正在开发中，尚未打包分发。当前只能从源码运行，配置格式与界面仍可能调整。

## 为什么要做它

起点是一个很具体的问题：

- 笔记是纯文本（`.txt`），想在**手机上翻看**，但不想为「同步」再装一套客户端、再注册一个账号；
- GitHub 天然满足「免费、有版本历史、任何设备都能读」，但它对写笔记的人太吵：仓库、分支、提交、推送，每一步都在要求你理解它的概念；
- 于是每次改完笔记，流程变成「敲完字 → 切到终端 → 三条命令 → 可能还要处理冲突」——**改动本身只花 10 秒，发布花了 3 分钟**。

FreePushNote 要做的就是把这个过程压成**一个按钮**：它把 git、文档站生成、发布这些事全收进后台，留在界面上的只有「你正在写的那篇笔记」和「它现在同步到哪了」。

## 它是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 一个能打开任意 txt 的**通用编辑器**（可设为 `.txt` 默认打开方式） | 不是知识管理软件（没有双链、没有数据库、没有标签体系） |
| 把**一个文件夹**的笔记发布成在线文档站的工具 | 不是云盘／实时同步（同步是**手动一键**，不后台偷跑） |
| GitHub 的**薄封装**：绑定一次账号，之后只管写和点 | 不是 Markdown 编辑器（输入是纯文本，Markdown 是给文档站生成的产物） |
| 单机软件，数据在你自己的磁盘和自己的仓库里 | 没有服务端、没有账号体系、不收集任何数据 |

## 现在能做什么

**写作**

- 打开 / 编辑 / 保存任意 txt，自动保存（输入停顿约 1 秒落盘）；拖放打开、最近打开列表
- 自动识别编码与换行符（UTF-8 / UTF-8 BOM / GBK，CRLF / LF）并在状态栏如实显示
- `Ctrl+F` 在当前这篇里查找；左栏可**按文件名**搜索全部笔记
- 状态栏：行列号、字数、编码、换行符、以及**当前笔记归属哪个仓库**（防止推错地方）
- 侧栏与右栏都能收起，编辑区字号可缩放

**发布到 GitHub**

- 绑定账号走 **OAuth Device Flow**：在浏览器里输一次验证码即可，不需要 client secret、不需要本地回调服务器
- 令牌用 **Windows DPAPI** 加密后存在本机，配置文件里只有账号名、没有明文令牌
- 「文件夹 = 分组 = 一个仓库」：绑定一次，此后这个文件夹里的笔记都归它管
- **只推送你勾选的文件**，其余文件不会被读取、更不会被上传
- 推送前先给你看这次会改什么（逐篇笔记的真实增删行数），确认后才提交
- 推送后自动生成 **docsify 文档站**并随仓库一起发布，配 GitHub Pages 就是可访问的在线阅读地址

> 注：仓库内置的 `client_id` 是开发者的 OAuth App。自己用没问题；若要以自己的名义分发，需要自建一个 OAuth App 并替换 `core/ghauth.py` 里的 `client_id`（Device Flow 不需要 client secret，创建成本很低）。

**从 GitHub 同步回来**

- **Pull**：把仓库里的更新拉回本地笔记文件夹
- 三方合并：两边改的位置不重叠就自动合并；**两边改到同一处时保留你的本地版本**，不做静默覆盖
- 写回前自动备份（`~/.pushnote/backups`，保留最近 5 次）；备份失败就不动你的文件
- **查看差异**：本地内容 ↔ 仓库版本的逐行对照（+ 绿 / − 红）

## 几个刻意的设计取舍

**1. `.txt` 是唯一真源**

仓库里还有 `<笔记>.md`、`index.html`、`_sidebar.md`、`assets/*` —— 这些**全部是每次推送时按原文重新生成的产物**，不参与同步。在 GitHub 网页上直接编辑它们，下次推送会被重新生成覆盖。要改内容，就改 `.txt`。

这条规则看起来反直觉，但它换来一件事：**永远不会出现「两边都改了同一份文件，但两边都不是真源」的混乱状态**。

**2. 文件夹 = 分组 = 一个仓库**

同步单元是文件夹而不是单篇笔记：绑定一次，文件夹里后续新增的笔记只需要勾选，不用重新走一遍关联仓库。不做「单文件绑仓库」是因为那样绑定关系会散落在几十个文件上，难以管理也无法撤销。

**3. 你的笔记文件夹里永远不会出现 `.git`**

git 仓库放在独立的中转区（`~/.pushnote/workspaces/<id>/`），每次推送前整块重建，只把白名单里的文件复制进去。所以：

- 笔记文件夹保持干净，不会被版本控制的内部文件污染；
- 「不想公开的文件」不是靠规则拦住的，而是**物理上根本没进过中转区**。

**4. 推送前必须让你看清楚**

推送拆成两阶段：先在本地整理出真实的变更清单（哪些笔记、各增删多少行），确认之后才提交并推送。**数字来自真实的 git 暂存区，不是估算**。

**5. 同步以「不丢东西」为第一优先**

Pull 只在「本地没改过」时才直接覆盖；本地改过的走三方合并；合并不了的（同一处相撞）保留本地并明确告知，把选择权交回给你。宁可少同步一次，不做静默覆盖。

**6. 除 Qt 之外零第三方依赖**

HTTP 用标准库 `urllib`，加密直接 `ctypes` 调系统 API。不引入 `requests` / `keyring` / `pywin32` —— 少一个依赖，少一份打包体积和兼容性风险。

## 技术栈

| | |
|---|---|
| 语言 | Python 3.10+（开发环境 3.13） |
| 界面 | PySide6 / Qt Widgets 6.12 |
| 存储 | 配置与令牌在 `~/.pushnote/`，笔记原文在你自己的文件夹里 |
| 依赖 | 运行时仅 PySide6 |
| 平台 | Windows（无边框窗口、DPAPI、任务栏行为都针对 Windows 实现） |

## 从源码运行

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install PySide6
run.bat
```
